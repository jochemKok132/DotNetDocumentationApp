Greedy Shift Scheduling (Worked Example)

Turn "we need two cashiers every weekday morning" into a week of concrete shifts: each slot is given to the qualified, available employee with the most contract hours still unplanned, and slots nobody can fill are left open for a human. A static function with no database access — so the rules are a handful of unit tests.

The inputs

Three plain collections go in; a list of shifts comes out. Nothing is read from or written to a database inside the generator.

  • Shift templates — name, which weekdays, start and end time, required role and how many staff.
  • Staff — role, contract hours per week and (optionally) the days and time windows they can work.
  • Days off — approved leave as a set of (employeeId, date) pairs.

Weekdays as a flags enum

A template says "Monday to Friday" with one value instead of five rows. The enum is a [Flags] bit set, and one helper maps .NET's DayOfWeek (Sunday = 0) onto it with Monday first:

Domain/Enums/WeekDays.cs + the mapper 
[Flags]
public enum WeekDays
{
    None      = 0,
    Monday    = 1,
    Tuesday   = 2,
    Wednesday = 4,
    Thursday  = 8,
    Friday    = 16,
    Saturday  = 32,
    Sunday    = 64,
}

// "Monday to Friday" is one value:  WeekDays.Monday | WeekDays.Tuesday | ... | WeekDays.Friday
// and "does this template run today?" is one call:  template.Days.HasFlag(weekDay)

// DayOfWeek: Sunday = 0 ... Saturday = 6.   (day + 6) % 7 shifts it so Monday = 0.
public static WeekDays ToWeekDay(DayOfWeek day) => (WeekDays)(1 << (((int)day + 6) % 7));

The generator

For each day of the week, for each template that runs that day, for each required slot, pick one employee. The selection is a filter followed by a deterministic ordering — no randomness, so the same inputs always give the same roster and the tests can assert exact results.

Application/Services/Scheduling/ScheduleGenerator.cs 
public static class ScheduleGenerator
{
    public static bool IsAvailable(Employee employee, DateOnly date, TimeOnly start, TimeOnly end) =>
        // no availability entered at all means "any time"
        employee.Availability.Count == 0 ||
        employee.Availability.Any(a => a.Day == date.DayOfWeek && ScheduleRules.Covers(a.AvailableFrom, a.AvailableUntil, start, end));

    public static List<ScheduledShift> Generate(
        DateOnly weekStart,
        IEnumerable<ShiftTemplate> templates,
        IEnumerable<Employee> staff,
        ISet<(Guid EmployeeId, DateOnly Date)> daysOff)
    {
        var employees = staff.Where(e => e.ContractHours > 0).ToList();
        var planned = employees.ToDictionary(e => e.Id, _ => 0m);          // hours given out so far this week
        var workingDays = new HashSet<(Guid, DateOnly)>();                 // one shift per person per day
        var shifts = new List<ScheduledShift>();

        var ordered = templates
            .Where(t => t.RequiredStaff > 0 && t.StartTime < t.EndTime)   // ignore broken templates
            .OrderBy(t => t.StartTime).ThenBy(t => t.Role).ThenBy(t => t.Name)
            .ToList();

        for (int offset = 0; offset < 7; offset++)
        {
            var date = weekStart.AddDays(offset);
            var weekDay = ToWeekDay(date.DayOfWeek);

            foreach (var template in ordered.Where(t => t.Days.HasFlag(weekDay)))
            {
                decimal hours = ScheduleRules.Hours(template.StartTime, template.EndTime);

                for (int slot = 0; slot < template.RequiredStaff; slot++)
                {
                    var employee = employees
                        .Where(e => e.Role == template.Role
                            && !workingDays.Contains((e.Id, date))
                            && !daysOff.Contains((e.Id, date))
                            && planned[e.Id] + hours <= e.ContractHours
                            && IsAvailable(e, date, template.StartTime, template.EndTime))
                        .OrderByDescending(e => e.ContractHours - planned[e.Id])   // most hours left first
                        .ThenBy(e => shifts.Count(s => s.EmployeeId == e.Id))    // then fewest shifts so far
                        .ThenBy(e => e.EmployeeId, StringComparer.Ordinal)         // then a stable tie-break
                        .FirstOrDefault();

                    if (employee is not null)
                    {
                        planned[employee.Id] += hours;
                        workingDays.Add((employee.Id, date));
                    }

                    // an unfillable slot is still created, just with no employee
                    shifts.Add(new ScheduledShift
                    {
                        Id = Guid.NewGuid(),
                        Date = date,
                        StartTime = template.StartTime,
                        EndTime = template.EndTime,
                        Role = template.Role,
                        EmployeeId = employee?.Id,
                    });
                }
            }
        }

        return shifts;
    }
}

Reading the .Where chain top to bottom gives the whole rule set: right role, not already working that day, not on leave, still within contract hours, and inside their availability window. The ordering spreads work evenly — whoever has the most hours left goes first — which is what stops the first person alphabetically from getting every shift.

Leaving gaps instead of failing

When nobody qualifies, the slot is still created with EmployeeId = null. A greedy algorithm can't always find a complete roster, and a half-filled week the manager can finish by hand is more useful than an exception. The UI shows open shifts, and the manager decides whether to hire cover or move someone.

Generating ahead on a timer

A small rules class decides which weeks to produce (WeekStart snaps any date back to its Monday; UpcomingWeeks yields the next four), and the automation worker calls the service each tick, which only creates weeks that don't exist yet — so a manager's manual edits to an already-generated week are never overwritten.

Shared/Common/ScheduleRules.cs 
public static class ScheduleRules
{
    public const int WeeksAhead = 4;

    // back up to Monday: (day + 6) % 7 is "days since Monday"
    public static DateOnly WeekStart(DateOnly date) =>
        date.AddDays(-(((int)date.DayOfWeek + 6) % 7));

    public static IEnumerable<DateOnly> UpcomingWeeks(DateOnly today)
    {
        var current = WeekStart(today);
        for (int week = 1; week <= WeeksAhead; week++)
            yield return current.AddDays(7 * week);
    }

    public static decimal Hours(TimeOnly start, TimeOnly end) =>
        Math.Round((decimal)(end - start).TotalHours, 2);

    public static bool Covers(TimeOnly availableFrom, TimeOnly availableUntil, TimeOnly start, TimeOnly end) =>
        availableFrom <= start && availableUntil >= end;
}

Testing it

Helpers build employees and templates with one line each, so every rule above is a short test with an exact expected roster:

UnitTests/Services/Scheduling/ScheduleGeneratorTests.cs 
private static readonly DateOnly Monday = new(2026, 11, 2);

private static Employee Staff(string number, EmployeeRole role, int hours, params (DayOfWeek Day, int From, int Until)[] availability)
{
    var employee = new Employee { Id = Guid.NewGuid(), EmployeeId = number, Role = role, ContractHours = hours };
    foreach (var (day, from, until) in availability)
        employee.Availability.Add(new EmployeeAvailability
        {
            Id = Guid.NewGuid(), EmployeeId = employee.Id, Day = day,
            AvailableFrom = new TimeOnly(from, 0), AvailableUntil = new TimeOnly(until, 0)
        });
    return employee;
}

private static ShiftTemplate Template(WeekDays days, int start, int end, EmployeeRole role = EmployeeRole.Cashier, int required = 1) => new()
{
    Id = Guid.NewGuid(),
    Name = "Shift",
    Days = days,
    StartTime = new TimeOnly(start, 0),
    EndTime = new TimeOnly(end, 0),
    Role = role,
    RequiredStaff = required,
};

[Fact]
public void Generate_OnlyAssignsEmployeesWithTheRole()
{
    var floor = Staff("000013", EmployeeRole.FloorWorker, 40);
    var cashier = Staff("000010", EmployeeRole.Cashier, 40);

    var result = ScheduleGenerator.Generate(Monday, [Template(WeekDays.Monday, 8, 14)], [floor, cashier], new HashSet<(Guid, DateOnly)>());

    Assert.Equal(cashier.Id, Assert.Single(result).EmployeeId);
}

[Fact]
public void Generate_NeverMoreThanContractHours()
{
    var cashier = Staff("000010", EmployeeRole.Cashier, 12);
    var days = WeekDays.Monday | WeekDays.Tuesday | WeekDays.Wednesday;

    var result = ScheduleGenerator.Generate(Monday, [Template(days, 8, 14)], [cashier], new HashSet<(Guid, DateOnly)>());

    Assert.Equal(2, result.Count(s => s.EmployeeId == cashier.Id));   // 2 x 6h = 12h
    Assert.Single(result, s => s.EmployeeId is null);                 // the third day stays open
}

[Fact]
public void Generate_OneShiftPerEmployeePerDay()
{
    var cashier = Staff("000010", EmployeeRole.Cashier, 40);

    var result = ScheduleGenerator.Generate(Monday,
        [Template(WeekDays.Monday, 8, 12), Template(WeekDays.Monday, 13, 17)], [cashier], new HashSet<(Guid, DateOnly)>());

    Assert.Single(result, s => s.EmployeeId == cashier.Id);
}

Things to watch

  • Greedy, not optimal. It never backtracks, so a different order of templates can leave a slot open that a smarter search would have filled. That's an accepted trade for a result that is fast, explainable and reproducible.
  • Sort order is part of the behaviour. Earlier shifts and the role order are filled first; change the OrderBy chain and you change who gets scarce staff.
  • Overnight shifts need two templates. Templates with StartTime >= EndTime are skipped, so a shift that crosses midnight has to be split at midnight — a TimeOnly pair can't say "ends tomorrow".
  • Hours come from the template, not the clock. ContractHours is a weekly cap compared against hours already planned in this generation; leave and sick days are handled via the daysOff set, not by lowering the cap.
